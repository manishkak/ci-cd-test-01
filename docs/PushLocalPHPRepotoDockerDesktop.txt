	• When you build and run the Docker container for your PHP app, here’s what happens under the hood:
	
	1. **Dockerfile instructions executed**
	
	   * Docker uses the `Dockerfile` you created in `/backend`.
	   * It starts from a **PHP + Apache base image**.
	   * It installs any extra PHP dependencies (like GD) and enables Apache features like `mod_rewrite`.
	   * It copies **all your PHP app files** from your local `backend` folder into the container’s `/var/www/html`.
	   * Sets permissions so Apache inside the container can read your files.
	   * Exposes port 80 (the default HTTP port inside the container).
	
	2. **Container runs Apache**
	
	   * When you run `docker run -p 8080:80 <image-name>`, Docker maps **container’s port 80** to **your host machine’s port 8080**.
	   * Apache inside the container serves the PHP files from `/var/www/html`.
	
	3. **Accessing `http://localhost:8080`**
	
	   * Your browser talks to **localhost:8080**.
	   * Docker forwards the request to the container’s Apache server.
	   * Apache serves the `index.php` (or whatever default file you have).
	
		○ So what you’re seeing in the browser is **exactly your PHP app running inside the container**, not from XAMPP. 
		○ That’s why it looks the same, but it’s now fully isolated in Docker.

	• Here’s what’s happening step by step on Docker Desktop:
		○ **Image (`backend-app`)** – This is your Docker image. Think of it as a **snapshot of your PHP app + Apache setup**. It contains all the files, installed dependencies, and configuration.
		○ **Container (`suspicious_faraday`)** – This is the **running instance** of your image. The container is what’s actually serving your app on a port (like 8080). You can have multiple containers from the same image.
		○ So essentially:
			§ * **Image** = blueprint
			§ * **Container** = live running app
